# 캐치 월드 포트폴리오 / 자기소개서 정리 (STAR)

> 이 문서는 작업 기록(커밋·SPEC·테스트)으로 **확인된 사실만** 적었다. 본인만 아는 항목은 **[확인 필요]** 로 두었다. 아직 공개 전이므로 접속자·클릭 수 같은 성과 수치는 쓰지 않는다(없는 성과를 만들지 않는다). 대신 **"무엇을 왜 만들었고, 어떻게 만들었고, 무엇을 배웠는가"** 로 설득한다.

---

## 0. 글의 방향

**지원 직무: 디지털 마케터 / 콘텐츠 마케터**

**핵심 메시지 한 줄**
> "메타버스와 AI 코딩(바이브코딩)에 관심이 많아서, 팀 프로젝트의 마케팅 전략을 말로만 제안하지 않고 직접 구현해 보았습니다."

**이 프로젝트가 보여 주는 것**
1. **호기심에서 출발한 실행력**: 새로운 기술(메타버스, AI 코딩)을 관심에서 끝내지 않고 실제 결과물로 만들어 봄
2. **마케터의 관점**: 타깃(취업 준비생)의 감정에서 콘텐츠를 만들고, 브랜드(캐치)로 이어지는 경로와 측정 구조를 설계함
3. **협업과 역할 분담**: 전략·환경분석·자료조사·PPT는 팀원이, 서비스 구현은 내가 맡아 한 팀으로 결과물을 완성함
4. **문제 해결과 개선**: 직접 써 보고 어색한 점을 찾아 수십 차례 고침. 비용·안전 위험을 먼저 계산함

**정직하게 말하는 방법 (중요)**
- 코드는 AI 도구(Claude Code)와 협업해 만들었다. "AI에게 요구사항을 정의하고, 결과를 검증하고, 방향을 결정하는 식으로 구현을 혼자 총괄했다"고 말한다. "코드를 직접 짰다"고 쓰지 않는다.
- 성과 수치가 없는 이유를 변명하지 않는다. "공개 전 단계라 팀 내부 테스트만 진행했고, 공개 후 지표를 볼 수 있도록 측정 구조를 먼저 만들었다"고 말한다.

## 1. 프로젝트 한 줄 소개

**캐치 월드** — 취업 준비생의 번아웃을 놀이로 풀어 주면서 구인구직 사이트 '캐치'를 자연스럽게 만나게 하는 **웹 3D 힐링 메타버스** (대학 디지털 마케팅 전략 팀 프로젝트, 캐치와 무관한 비공식 학사 과제)

- 배포 주소: https://catch-world.vercel.app
- 코드 저장소: https://github.com/amuk60/catch-world
- 기간: 2026-11-11 ~ 진행 중 (과제 마감 11/27)
- 기술: Three.js(웹 3D), JavaScript, Vercel(배포), Supabase Realtime(멀티플레이), Google Analytics 4, Claude Code(AI 개발 도구)

### 내 역할 (팀 5명)
- **기획**: 팀원 모두와 함께 (콘셉트 "번아웃 소각장", 소각장/세탁소/면접장 아이디어는 팀 기획안에서 시작)
- **구현 전체**: 내가 혼자 맡음 — 요구사항 정리, AI와 협업한 개발 총괄, 검수·수정 요청, 배포, 분석 도구 연결
- **다른 팀원**: PPT, 환경분석, 전략 자료조사 담당 (제출용 전략 자료에 이 서비스의 화면과 링크가 들어감)
- [확인 필요] 팀원의 테스트·피드백 참여 정도(아래 사례 B에 활용)

### 결과물 규모 (코드 기록으로 확인된 사실)
| 항목 | 내용 |
|---|---|
| 콘텐츠 | 3D 마당(소각장·파쇄기·모닥불·마시멜로 굽기), 캐치 면접장, 마음 세탁소, 포춘쿠키 상점 — 4개 체험 공간 |
| 기능 | 실시간 멀티플레이(아바타·말풍선·빨래줄 공유), 키보드·마우스 이동, 효과음, 닉네임·응원말 |
| 코드 | 소스 약 1만 5천 줄(JavaScript) |
| 품질 | 자동 테스트 827개 통과 |
| 배포·측정 | 공개 URL 배포 완료, GA4 이벤트 약 20종 설계 |
| 진행 | 약 1주일간 커밋 80여 개 |

## 2. STAR 사례 (포트폴리오 본문용)

### 사례 A. 관심을 실물로: 메타버스를 직접 만들어 본 경험 (대표 사례)

- **S(상황)**: 디지털 마케팅 전략 팀 프로젝트에서 캐치의 인지도와 유입을 높이는 방안을 제안해야 했다. 팀 5명 중 개발자는 없었다. 나는 평소 메타버스와 AI를 활용한 개발(바이브코딩)에 관심이 많았지만, 해 본 적은 없었다.
- **T(과제)**: 전략 PPT에 "메타버스를 활용한 체험형 마케팅"이라고 쓰는 데서 끝내지 않고, 실제로 접속해 체험되는 결과물로 만들어 아이디어가 현실에서 어떻게 보이는지 직접 확인한다. 구현은 내가 맡는다.
- **A(행동)**
  1. 팀이 함께 만든 기획안을 받아, 질문으로 목표·대상·범위·성공 기준을 좁혀 **SPEC 문서**로 정리했다. 정해지지 않은 것은 추측하지 않고 확인 필요 항목으로 남겼다.
  2. 일정을 역산해 **눈으로 확인 가능한 작은 단계**로 쪼개고, 매 단계를 직접 플레이해 승인한 뒤 다음으로 넘어갔다.
  3. 처음 만든 2D 프로토타입이 의도한 분위기와 다르다는 것을 직접 보고 **3D로 전환**하는 결정을 했다.
  4. AI 코딩 도구에게 구현을 맡기되, 무엇을 만들지·어떻게 검증할지·어떤 방향으로 고칠지는 내가 정했다.
  5. GitHub·Vercel로 직접 배포하고, Supabase(멀티플레이)·GA4(분석)까지 계정 설정부터 연결했다.
- **R(결과)**: 누구나 접속할 수 있는 3D 메타버스를 공개 주소로 배포했다. 전략 자료에 실제 화면과 링크를 넣을 수 있게 되어, 팀의 제안이 "아이디어"에서 "만들어 본 결과물"이 되었다.
- **배운 점**: 비개발자가 AI와 일할 때 병목은 코딩이 아니라 **요구사항의 명확함과 검수 기준**이었다. 이 경험으로 새로운 기술을 두려워하지 않고 직접 해 보고 배우는 방식이 몸에 붙었다.

### 사례 B. 직접 써 보고 반복 개선: "소각장" 콘텐츠

- **S**: 첫 버전의 소각장은 버튼 하나로 종이를 태우는 단순한 반복이었다. 직접 해 보니 동작이 어색했고(던지는 손 방향, 불필요한 한숨 동작), 팀원 피드백도 "금방 지루하다", "스트레스 지수가 빨리 안 줄어든다"였다.
- **T**: 같은 행동의 반복이 아니라 "하기 싫은 일을 없애 버리는 시원함"이 느껴지는 경험으로 바꾼다.
- **A**
  1. 어색한 점을 하나씩 구체적인 수정 요청으로 바꿨다(던지는 손 변경, 종이가 불합격 통지서임을 알아보게 크기·도장 개선, 길을 막는 나무토막 재배치).
  2. 팀원 피드백("자소서·이력서를 매번 다시 쓰는 게 힘들어서 태우는 것")을 **물건 5종 선택(자소서·이력서 뭉치, 불합격 통지서, 인적성 교재, 취업 잔소리 쪽지, 오로라 가루)과 상황별 멘트**로 바꿨다.
  3. 파쇄는 "던지지 말고 직접 가서 갈아버리게" 의견을 받아 **파쇄기를 분리하고 캐릭터가 걸어가 투입구에 종이를 얹어 갈리는 과정**으로 재설계했다.
  4. 불멍은 **1인칭 마시멜로 굽기 미니게임**(판마다 다른 타이밍, 좁은 성공 구간)으로 바꾸되, 실패해도 스트레스가 줄도록 해서 힐링 콘셉트를 지켰다.
- **R**: 단일 버튼 반복에서 선택·타이밍·멘트가 있는 약 7초짜리 연출로 바뀌었다. 팀원 피드백을 반영한 수정을 여러 번 반복했다.
- **포인트**: "불편하다"를 "무엇이 어떻게 달라져야 한다"로 번역해 지시하는 능력, 그리고 피드백 → 수정 → 재확인의 반복.

### 사례 C. 타깃 감정을 콘텐츠와 카피로 (콘텐츠 마케터용)

- **S**: 취업 준비생은 서류 탈락, 같은 자소서를 끝없이 고치는 일, 면접 압박, 주변 잔소리에 지쳐 있다. 일반 구직 광고는 이 감정에 닿지 않는다.
- **T**: 광고처럼 보이지 않고, 타깃이 "내 얘기다" 하며 웃고 공감하는 콘텐츠를 만든다. 그 끝에서 캐치로 자연스럽게 이어지게 한다.
- **A**
  1. 태울 물건마다 속마음을 대신 말해 주는 멘트를 썼다. 예: "서류도 면접도 버거운데 필기까지… 잠깐 쉴게", "힘 빠지는 잔소리는 프리패스! 응원만 받을게요", "불합격도 합격이다! 기죽지 말자".
  2. 세탁소는 "월요일 냄새 세탁 중…", "야근 찌든 때 표백 중…"처럼 직장 초년 정서를 담았고, 면접장은 압박 질문 12개와 정석·솔직·엉뚱 세 가지 답변을 유머로 썼다.
  3. 포춘쿠키 운세 24개를 6개 주제로 나누고 **내용과 이어지는 캐치 버튼**(예: 면접운 → "캐치 면접 후기 보러가기")을 붙였다.
  4. 위로·응원 톤을 일관되게 유지하고, 캐치는 강요하는 광고가 아니라 해결책을 건네는 친구로 등장시켰다.
- **R**: 콘텐츠 전반이 타깃의 감정을 기준으로 일관되게 설계되었다. [확인 필요] 팀원이 웃었거나 공감했다고 한 말(원문)이 있으면 한 줄 인용.
- **포인트**: 인사이트 → 콘텐츠 → 카피 → 행동 유도를 한 흐름으로 설계.

### 사례 D. 마케팅 목표를 제품 안에 연결하고 측정 구조까지 설계 (디지털 마케터용)

- **S**: 콘텐츠가 재미있어도 캐치로 이동하지 않으면 목표(인지도·유입)에 기여하지 못한다. 그리고 측정하지 않으면 무엇이 효과적인지 알 수 없다.
- **T**: 진입 → 참여 → 감정 해소 → 캐치 이동의 흐름을 설계하고, 단계별로 측정할 수 있게 한다.
- **A**
  1. CTA를 게임을 방해하지 않는 순간에 분산 배치했다: 스트레스 지수 20 이하(비차단 카드), 0(중앙 팝업), "면접 갈 준비 완료!"(새 셔츠를 입은 순간), 포춘쿠키 운세 결과 옆.
  2. 캐치로 가는 링크에 **UTM**(출처·매체·캠페인)을 붙여 경로를 구분하게 했다.
  3. GA4에 접속, 핵심 활동, 목표 달성, 캐치 이동, 공유 이벤트 약 20종을 설계했다. 개발 중 접속은 통계에서 제외해 데이터 오염을 막았다.
- **R**: 공개 후 지표(접속자, 캐치 링크 클릭률, 경로별 비교)를 바로 볼 수 있는 측정 구조를 갖췄다. (현재는 공개 전이라 수치 없음)
- **포인트**: "목표 → 흐름 설계 → 지표 → 개선"의 마케팅 사이클을 구현 단계에서부터 고려함.

### 사례 E. 제약을 먼저 계산하는 판단: 멀티플레이

- **S**: 팀의 원래 목표는 여러 명이 같이 접속하는 것이었다. 하지만 무료 서버에는 메시지 한도가 있었고, 자유 채팅은 욕설·악용 위험이 있었다. 마감도 촉박했다.
- **T**: 한도를 넘지 않고, 안전하며, 안 되면 빨리 접을 수 있는 방식으로 멀티플레이를 시도한다.
- **A**
  1. "해 보고 안 되면 빨리 포기한다"는 기준으로 짧은 시험 작업부터 진행했다.
  2. 접속자가 늘면 서로 보내는 메시지가 인원 제곱으로 늘어난다는 점을 계산해 **방 인원 6명 상한과 자동 분배**를 설계했다.
  3. 자유 채팅 대신 **정해진 인사·응원말**만 허용해 모더레이션 위험을 구조적으로 없앴고, 닉네임은 금칙어·연락처를 검사했다.
  4. 작업 중 서버 비밀 키를 대화에 잘못 붙여넣은 것을 알아차리고 즉시 폐기했다.
- **R**: 아바타·말풍선·빨래줄이 공유되는 실시간 멀티플레이를 무료 한도 안에서 운영 가능한 구조로 만들었다.
- **포인트**: 기능 욕심보다 비용·보안·운영 위험을 먼저 따지는 판단, 실수를 숨기지 않고 바로잡는 태도.

### 사례 F. AI 협업 방식을 설계해 품질 지키기 (바이브코딩 경험)

- **S**: AI가 만든 결과는 빠르지만 틀리거나 일관성이 깨질 수 있다. 코드를 못 읽는 사람이 품질을 보장하기 어렵다.
- **T**: 코드를 읽지 못해도 결과를 믿을 수 있는 검증 방식을 만든다.
- **A**
  1. 작업을 작은 단위로 나눠 **각각 별도 작업 공간**에서 진행시키고, 독립적인 작업은 동시에 시켜 시간을 줄였다.
  2. 모든 작업에 **자동 테스트**를 요구하고, 결과를 **화면 캡처로 확인**했다. 소리는 수치로 1차 검증한 뒤 직접 듣고 피드백했다.
  3. 문제가 생기면 원인부터 물었다(예: 불 소리가 "지지직"거림 → 원인이 초당 수천 개의 알갱이가 뭉개지는 구조라는 점을 확인해 방식을 바꿈).
  4. 결정 사항을 SPEC 문서에 기록해 대화가 길어져도 기준이 흔들리지 않게 했다.
- **R**: 비개발자가 약 1주일 안에 4개 체험 공간과 멀티플레이를 가진 서비스를 만들고 운영(배포·측정 연결)했다.
- **포인트**: AI를 잘 쓰는 능력은 코딩이 아니라 **문제 정의, 검증 기준, 방향 판단**이라는 확신.

## 3. 자기소개서 문단 (직무별)

### 3-1. 디지털 마케터 (약 700자, 1순위)

평소 메타버스와 AI를 활용한 개발(바이브코딩)에 관심이 많았지만 경험은 없었습니다. 디지털 마케팅 전략 팀 프로젝트에서 캐치의 인지도와 유입을 높이는 방안으로 팀이 함께 '번아웃 소각장' 콘셉트의 메타버스를 기획했고, 팀원이 환경분석과 전략 자료조사, PPT를 맡는 동안 저는 이 아이디어를 실제 접속 가능한 서비스로 구현하는 일을 맡았습니다. 개발자가 없어 AI 도구와 협업했고, 저는 요구사항 정의와 검수 기준, 수정 방향을 책임졌습니다. 서류 탈락과 자소서 반복 수정이라는 타깃의 스트레스를 '서류를 태우고, 마음을 빨고, 면접을 받아치는' 놀이로 바꾸고, 캐치 링크를 목표 달성 카드와 면접 준비 완료 팝업, 운세 결과 옆 버튼처럼 흐름을 방해하지 않는 곳에 배치했습니다. 링크에는 UTM을 붙이고 GA4 이벤트를 설계해 공개 후 경로별 효과를 확인할 수 있게 했습니다. 아직 공개 전이라 성과 수치는 없지만, 아이디어를 직접 구현해 보며 **타깃 감정에서 콘텐츠를 만들고 측정까지 설계하는 일의 전 과정**을 경험했습니다. 이 호기심과 실행력으로 [회사]에서 새로운 채널과 도구를 빠르게 익혀 직접 시도하는 디지털 마케터가 되겠습니다.

### 3-2. 콘텐츠 마케터 (약 700자)

취업 준비생에게 가장 와닿는 콘텐츠는 정보가 아니라 공감이라고 생각했습니다. 팀 프로젝트로 만든 3D 체험 서비스 '캐치 월드'에서 저는 구현을 맡으며, 서류 탈락과 자소서 반복 수정, 취업 잔소리를 게임 소재로 삼았습니다. "서류도 면접도 버거운데 필기까지… 잠깐 쉴게", "불합격도 합격이다! 기죽지 말자", "힘 빠지는 잔소리는 프리패스! 응원만 받을게요"처럼 타깃의 속마음을 대신 말해 주는 멘트를 물건마다 썼고, 세탁소에는 "월요일 냄새 세탁 중…", 면접장에는 정석·솔직·엉뚱 세 가지 답변을 담았습니다. 포춘쿠키 운세 24개는 주제별로 나눠 운세와 이어지는 캐치 버튼으로 마무리했습니다. 위로와 응원 톤을 일관되게 유지하고, 캐치는 강요하는 광고가 아니라 해결책을 건네는 친구로 등장시켰습니다. 팀원 피드백을 받아 문구와 연출을 여러 번 고쳤습니다. 이 경험으로 **타깃의 감정에서 출발해 브랜드로 자연스럽게 이어지는 콘텐츠를 반복 개선하는 방법**을 배웠고, 이를 [회사]의 콘텐츠에 적용하겠습니다.

### 3-3. 도전·성장 / 새로운 기술 활용 문항용 (약 500자)

메타버스와 AI 코딩에 관심은 있었지만 경험이 없어서, 팀 프로젝트에서 구현을 자원해 직접 해 보았습니다. 코딩을 몰라도 가능한지가 가장 큰 의문이었습니다. 결과적으로 병목은 코딩이 아니라 **무엇을 만들지 명확히 정의하는 일과 결과를 검증하는 일**이었습니다. 요구사항을 질문으로 좁혀 문서로 남기고, 작은 단계로 나눠 매번 직접 플레이해 확인했고, 어색한 부분은 구체적인 수정 요청으로 바꿔 반복했습니다. 서버 비용 한도와 욕설 위험 같은 제약은 기능을 만들기 전에 계산해 설계에 반영했고, 비밀 키를 잘못 노출한 실수는 즉시 바로잡았습니다. 이 과정에서 새로운 도구를 두려워하지 않고 일단 만들어 보며 배우는 방식이 제 강점이 되었습니다.

### 3-4. 협업 문항용 포인트
- 역할 분담: 전략·자료조사·PPT(팀원) ↔ 구현(나). 서로의 결과물이 연결되도록 서비스 화면과 링크를 전략 자료에 쓸 수 있게 공유
- 피드백 수용: 팀원의 의견("소각 모션이 단순해졌다", "세탁 멘트와 이펙트가 있으면 좋겠다")을 우선순위로 정리해 반영
- [확인 필요] 의견이 달랐던 순간과 조율한 방법 1개 (이 문서에는 기록이 없어 만들어 쓰지 않았다)
