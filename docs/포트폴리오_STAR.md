# 캐치 월드 포트폴리오 / 자기소개서 정리 (STAR)

> 이 문서는 작업 기록(커밋·SPEC·테스트)에서 **확인된 사실만** 적었다. 본인만 알 수 있는 항목은 **[확인 필요]** 로 두었으니 채운 뒤 제출한다. 결과 수치(접속자, 클릭 수 등)는 GA4에서 가져와 넣는다. 없는 성과를 만들어 쓰지 않는다.

---

## 0. 먼저 정할 것 (글의 방향)

**지원 직무: 디지털 마케터 / 콘텐츠 마케터.** 이 문서의 강조점은 개발 자체가 아니라 아래 네 가지다.
1. **타깃 인사이트**: 취업 준비생의 진짜 불편(서류 탈락, 자소설 반복, 면접 압박, 잔소리)을 콘텐츠 소재로 바꿈
2. **콘텐츠·카피**: 소각 멘트, 세탁 멘트, 면접 질문·답변, 포춘쿠키 운세 24개, CTA 문구 — 모두 타깃의 감정에서 출발
3. **퍼널·측정**: 체험 → 감정 해소 → 캐치로 이동. UTM과 GA4 이벤트로 경로별 효과 측정
4. **실행력**: 개발자 없이 기획→제작→배포→측정까지 끝까지 해냄 (AI 도구 활용)

개발 이야기는 "어떻게 만들었는가"의 보조 설명으로만 쓰고, 면접관이 마케터로서 궁금해할 **"왜 이 콘텐츠였나, 무엇을 측정했나, 결과가 어땠나"** 를 먼저 말한다.


이 프로젝트의 가장 정직하고 강한 정체성은 **"개발자 없이, AI 코딩 도구와 협업해 기획 → 구현 → 배포 → 측정까지 끝낸 사람"** 이다.
코드를 직접 한 줄씩 짠 것처럼 쓰면 면접에서 바로 무너진다. 대신 아래를 본인이 한 일로 전면에 둔다.

- 무엇을 만들지 정하고(기획), 모호한 것을 질문으로 좁히고(요구사항 정리), 우선순위를 정함
- 결과물을 직접 써 보고 "어색하다/아쉽다"를 구체적인 수정 요청으로 바꿈(품질 판단, 사용자 관점)
- 팀원·사용자 피드백을 모아 반영 순서를 정함
- 계정·배포·분석 도구를 직접 만들고 연결함(GitHub, Vercel, Supabase, GA4)
- AI가 만든 결과를 테스트·화면 확인으로 검증하는 방식을 설계함

**[확인 필요] 본인 역할**: 팀 5명 중 본인이 맡은 역할(기획/PM/QA/마케팅 등)과 다른 팀원의 기여를 한 줄로 정리한다. 팀 프로젝트이므로 "팀이 한 일"과 "내가 한 일"을 구분해 쓴다.

## 1. 프로젝트 한 줄 소개

**캐치 월드** — 취업 준비생의 번아웃을 놀이로 풀어 주면서 구인구직 사이트 '캐치'를 자연스럽게 만나게 하는 **웹 3D 힐링 메타버스** (학사 과제용 비공식 프로젝트, 캐치와 무관)

- 배포 주소: https://catch-world.vercel.app
- 코드 저장소: https://github.com/amuk60/catch-world
- 기간: 2026-11-11 ~ 진행 중(마감 11/27). 기록상 1주일 안에 82개 커밋
- 사용 기술: Three.js(3D), 순수 JavaScript, Vercel(배포), Supabase Realtime(멀티플레이), Google Analytics 4, Claude Code(AI 개발 도구)

| 항목 | 내용 |
|---|---|
| 콘텐츠 | 3D 마당(소각장·파쇄기·모닥불·마시멜로 굽기), 캐치 면접장, 마음 세탁소, 포춘쿠키 상점 — 총 4개의 체험 공간 |
| 코드 규모 | 소스 약 1만 5천 줄(JavaScript) |

| 측정 | GA4 이벤트 약 20종(소각·세탁·면접·마시멜로·포춘쿠키·캐치 링크 클릭) |
| 결과 | [확인 필요] 접속자 수 / 평균 체류 시간 / 캐치 링크 클릭 수 (GA4) |

## 2. STAR 사례 (포트폴리오 본문용)

### 사례 A. 개발자 없이 '기획서 → 실제 서비스'까지: 프로젝트 전체

- **S(상황)**: 디지털 마케팅 전략 팀 프로젝트에서 캐치의 인지도와 신규 유입을 높이는 방안을 제안해야 했다. 팀 5명 중 개발자가 없었고, 마감까지 약 2주였다. 보통은 PPT 제안으로 끝나는 과제였다.
- **T(과제)**: 말로만 하는 전략이 아니라, 누구나 접속해 체험할 수 있는 실제 서비스를 만들어 "취업 준비생이 스스로 찾아오고 캐치로 이동하는" 경험을 검증 가능한 형태로 보여 준다.
- **A(행동)**
  1. 팀 기획안을 받아 질문 인터뷰 방식으로 **목표·사용자·문제·범위·성공 기준**을 정리해 SPEC 문서로 만들었다. 정해지지 않은 것은 추측하지 않고 `[확인 필요]`로 분리했다.
  2. 일정을 역산해 **"눈으로 확인 가능한 작은 단계"**로 쪼갰다(월드 이동 → 캐릭터 → 소각 → 팝업 → 공유 → 배포). 단계마다 직접 화면을 보고 승인한 뒤에만 다음으로 넘어갔다.
  3. 초기에 만든 2D 프로토타입이 의도한 분위기와 다르다는 것을 직접 확인하고, **3D 전환을 결정**했다(비용이 늘지만 레퍼런스의 느낌을 살리는 쪽이 목표에 맞다고 판단).
  4. AI 코딩 도구에게 구현을 맡기되, 요구사항·검수 기준·수정 방향은 사람이 정하는 구조를 만들었다.
  5. GitHub·Vercel로 직접 배포하고 GA4를 연결해 측정까지 완료했다.
- **R(결과)**: 접속 가능한 3D 서비스를 공개 주소로 배포했고, 이벤트 측정까지 연결했다. [확인 필요] 접속자/클릭 수, 평가 결과.
- **배운 점**: 비개발자가 AI와 일할 때 병목은 코딩이 아니라 **요구사항의 명확함과 검수 기준**이었다.

### 사례 B. 사용자(팀원) 피드백으로 핵심 경험을 반복 개선: "소각장"

- **S**: 첫 버전의 소각장은 버튼 하나로 종이를 태우는 단순한 반복이어서, 팀원이 "금방 지루하고 스트레스가 빨리 줄지도 않는다"고 피드백했다. 직접 해 봐도 모션이 어색했다(한숨·고개 젓기 동작, 던지는 손 방향, 종이가 뭔지 알아보기 힘듦).
- **T**: 같은 행동의 반복이 아니라 "하기 싫은 것을 없애버리는 시원함"이 느껴지는 경험으로 바꾼다.
- **A**
  1. 사용자 눈으로 문제를 하나씩 구체화해 요청했다: 던지는 손 모션 수정, 종이가 불합격 통지서임을 알아보게 크기·도장 개선, 길을 막는 나무토막 재배치.
  2. 팀원 피드백("자소서·이력서를 매번 다시 쓰는 게 힘들어서 태우는 것")을 **물건 5종 선택(자소서·이력서 뭉치, 불합격 통지서, 인적성 교재, 취업 잔소리 쪽지, 오로라 가루)과 상황별 멘트**로 바꿨다.
  3. 파쇄 동작은 "던지지 말고 직접 가서 갈아버리게"라는 의견을 받아 **파쇄기를 분리하고 걸어가 종이를 투입구에 얹어 갈리는 과정**으로 재설계했다.
  4. 지루한 불멍을 **1인칭 마시멜로 굽기 미니게임**(판마다 다른 타이밍, 좁은 성공 구간, 결과별 보상 3~8)으로 바꿨다. 어렵게 하되 실패해도 지수는 줄도록 설계해 힐링 콘셉트를 지켰다.
- **R**: 동작 하나가 7초 안팎의 연출 있는 경험으로 바뀌었고, 사용자가 같은 행동에서도 선택·타이밍·멘트로 다른 결과를 얻게 됐다. [확인 필요] 팀 시험 후 반응/체류 시간 변화.
- **포인트**: "불편하다"를 "무엇이 어떻게 달라져야 한다"로 번역해 지시하는 능력.

### 사례 C. 설계 단계에서 비용·안전 위험을 먼저 계산: 멀티플레이

- **S**: 팀의 원래 목표는 여러 명이 동시에 접속하는 것이었다. 하지만 무료 서버(Supabase)의 메시지 한도가 있고, 채팅을 열면 욕설·악용 위험이 있었다. 마감은 얼마 남지 않았다.
- **T**: 한도를 넘지 않고, 안전하며, 안 되면 빨리 접을 수 있는 방식으로 멀티플레이를 도입한다.
- **A**
  1. "해 보고 안 되면 빨리 포기하는 게 일정상 더 빠르다"는 기준으로 **시험 작업(스파이크)**부터 진행했다.
  2. 접속자가 늘면 서로에게 보내는 메시지가 인원 제곱으로 늘어난다는 점을 계산하고, **방 인원 6명 상한과 방 자동 분배(샤딩)**로 초당 전송량을 한도 아래로 설계했다. 가만히 있거나 탭이 숨겨지면 전송을 멈추게 했다.
  3. 자유 채팅 대신 **미리 정한 인사·응원말 프리셋**만 허용해 모더레이션 위험을 구조적으로 없앴다. 닉네임은 금칙어·연락처 패턴을 검사하고, 상대가 보낸 값도 받는 쪽에서 다시 검증하게 했다.
  4. 작업 중 서버 비밀 키를 채팅에 잘못 붙여넣은 것을 인지하고 **즉시 폐기**했다.
  5. 방문자가 같이 쓰는 공간에서 충돌(같은 면접관 사용)이 생기자 **면접관-의자 1:1 담당제**로 해결했다.
- **R**: 동시 접속하는 아바타·말풍선·빨래줄 공유 멀티플레이를 무료 한도 안에서 운영 가능한 구조로 구현했다. [확인 필요] 팀 동시 접속 시험 결과.
- **포인트**: 기능 욕심보다 비용·보안·운영 리스크를 먼저 따지는 판단.

### 사례 D. 마케팅 목표를 제품 안에 연결하고 측정 가능하게 설계: 캐치 유입(CTA)

- **S**: 서비스가 재미있어도 캐치로 이어지지 않으면 과제 목표(브랜드 인지도·유입)를 달성하지 못한다.
- **T**: 게임의 흐름을 깨지 않으면서 "캐치로 가는 길"을 자연스럽게 배치하고, 그 효과를 숫자로 확인한다.
- **A**
  1. 스트레스 지수 구간별 **두 단계 팝업**(목표 달성 시 비차단 측면 카드, 0이 되면 중앙 팝업)으로 부담 없이 캐치 링크를 노출했다.
  2. 의상 스토리(소각으로 더러워짐 → 세탁 → 새 셔츠를 입고 "면접 갈 준비 완료!")의 **끝에 캐치 이동 팝업**을 두었다.
  3. 포춘쿠키 상점을 만들어, 운세를 6분류로 나누고 **운세 내용과 연결된 캐치 버튼**(예: 면접운 → "캐치 면접 후기 보러가기")을 붙였다. 링크에 출처 표시(UTM)를 붙여 어떤 경로로 왔는지 구분되게 했다.
  4. GA4를 연결해 접속·행동·CTA 클릭 이벤트를 설계했다(개발 중 접속은 통계에서 제외).
- **R**: 서비스 이용 흐름 곳곳에 캐치 이동 경로를 두고, 경로별 클릭을 측정할 수 있는 구조를 갖췄다. [확인 필요] 캐치 링크 클릭 수, 경로별 비교.
- **포인트**: 기획의 목적(마케팅 성과)을 기능 설계와 측정으로 연결하는 사고.

### 사례 E. AI와 일하는 방식을 설계해 품질을 지킴 (프로세스)

- **S**: AI가 만든 코드는 빠르지만 틀리거나 일관성이 깨질 수 있어, 비개발자가 품질을 보장하기 어렵다.
- **T**: 코드를 읽지 못해도 결과를 믿을 수 있는 검증 방식을 만든다.
- **A**
  1. 작업을 작은 단위로 나누고 **각 단위는 별도 작업 공간(브랜치/워크트리)**에서 진행해 서로 영향을 주지 않게 했다. 독립적인 작업은 동시에 진행해 시간을 줄였다.
  2. 모든 작업에 **자동 테스트**를 요구해 822개가 통과해야만 합치도록 했다.
  3. 결과를 **화면 캡처로 확인**하고, 소리처럼 직접 들어야 하는 것은 수치로 1차 검증한 뒤 내가 직접 듣고 피드백했다(예: 불 소리가 "지지직"거린다 → 원인이 초당 수천 개의 알갱이가 뭉개지는 것임을 찾아 구조를 바꿈).
  4. 결정 사항은 SPEC 문서에 기록해, 대화가 길어져도 기준이 흔들리지 않게 했다.
- **R**: 비개발자도 일관된 품질의 서비스를 짧은 기간에 만들고 운영(배포·되돌리기·측정)할 수 있음을 보였다.
- **포인트**: AI를 쓰는 사람의 역량 = 문제를 정의하고, 검증 기준을 세우고, 방향을 판단하는 것.

### 사례 F. 타깃 인사이트를 콘텐츠와 카피로 바꿈 (콘텐츠 마케터용 핵심)

- **S**: 취업 준비생은 서류 탈락, 같은 자소서를 끝없이 고치는 일, 면접 압박, 주변 잔소리에 지쳐 있다. 일반적인 구직 광고 문구는 이 감정에 닿지 않는다.
- **T**: 광고처럼 보이지 않고, 타깃이 "내 얘기다" 하고 웃으며 공감해 계속 머무는 콘텐츠를 만든다. 그 끝에서 캐치로 자연스럽게 이어지게 한다.
- **A**
  1. 팀 아이디어("소각장")를 타깃 감정에 맞춰 구체화했다. 태울 물건을 **자소서·이력서 뭉치, 불합격 통지서, 인적성 교재, 취업 잔소리 쪽지**로 정하고, 각 물건에 상황이 담긴 멘트를 붙였다(예: "서류도 면접도 버거운데 필기까지… 잠깐 쉴게", "힘 빠지는 잔소리는 프리패스! 응원만 받을게요", "불합격도 합격이다! 기죽지 말자"). 하기 싫은 일을 게임에서라도 없애는 **카타르시스**를 톤의 기준으로 잡았다.
  2. 세탁소에는 "월요일 냄새 세탁 중…", "야근 찌든 때 표백 중…"처럼 **직장 초년 정서**를 담은 카피를, 면접장에는 압박 질문 12개와 정석/솔직/엉뚱 3가지 답변을 유머로 썼다.
  3. 포춘쿠키 운세 24개를 6개 주제(면접운, 서류운, 성장운, 휴식운, 멘탈운, 행운)로 분류해 **내용에 맞는 캐치 버튼**을 붙였다(예: 면접운 → "캐치 면접 후기 보러가기").
  4. 응원·위로 톤을 일관되게 유지하고, 캐치는 "해결책을 제시하는 친구"로 등장시켰다(강요하는 광고 금지).
- **R**: 콘텐츠 전반이 타깃의 감정을 기준으로 일관되게 설계됐다. [확인 필요] 팀원/시험 사용자 반응(웃었다, 공감했다 등 원문), 체류 시간.
- **포인트**: "인사이트 → 콘텐츠 → 카피 → 행동 유도"를 한 흐름으로 설계한 경험.

### 사례 G. 퍼널 설계와 측정: 디지털 마케터용 핵심

- **S**: 콘텐츠가 재미있어도 캐치로 이동하지 않으면 마케팅 목표(인지도·유입)에 기여하지 못한다. 그리고 측정하지 않으면 무엇이 효과적인지 알 수 없다.
- **T**: 진입 → 참여 → 감정 해소 → 캐치 이동의 **퍼널**을 설계하고, 단계별 지표를 정한다.
- **A**
  1. 퍼널을 정의했다: 접속(`game_start`) → 핵심 활동 참여(`action_done`, `enter_space`, `interview_answer`, `marshmallow`, `fortune_crack`) → 목표 달성(`goal_reached`, `game_clear`) → 캐치 이동(`cta_click`, `banner_click`, `fortune_cta_click`) → 공유(`share_image`, `share_link`).
  2. CTA를 **타이밍별로 분산 배치**했다: 지수 20 이하(비차단 카드), 지수 0(중앙 팝업), 면접 준비 완료(새 셔츠 입은 순간), 포춘쿠키 운세 결과 옆. 게임을 방해하지 않는 위치를 기준으로 삼았다.
  3. 캐치로 가는 링크에 **UTM**(출처·매체·캠페인)을 붙여 운세 종류별로 도착 경로를 구분하게 했다. 개발 중 접속은 통계에서 제외해 데이터 오염을 막았다.
  4. 접속자 수(누적), 캐치 링크 클릭 수를 핵심 지표로 정하고 GA4에서 핵심 이벤트로 관리하도록 설정했다.
  5. 전송량·안정성 같은 운영 위험은 사전에 계산해 서비스가 끊기지 않게 했다.
- **R**: 단계별 이탈·전환을 볼 수 있는 측정 체계를 갖췄다. [확인 필요] GA4 수치: 사용자 수, 행동별 참여 수, CTA 클릭률(= 클릭 / 접속), 가장 효과적이었던 CTA 위치.
- **포인트**: 목표 → 퍼널 → 지표 → 실행 → 개선의 사이클을 직접 돌려 본 경험. 수치가 작더라도 "무엇을 보고 어떻게 개선할지" 설명할 수 있어야 한다.
